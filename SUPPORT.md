# Support

Mintkey is **pre-alpha software** — not intended for production use. Support is
best-effort. There are no SLOs, no support contracts, and no guarantee of
response time.

---

## Bug reports

Use the bug report issue template on GitHub:

**[Open a bug report](https://github.com/WeLikeCode/mintkey/issues/new?template=bug_report.yml)**

Before opening, search [existing issues](https://github.com/WeLikeCode/mintkey/issues)
to avoid duplicates. Include the Docker Compose version, host OS, and Mintkey
commit SHA. Remove all credentials, tokens, and PII before submitting.

---

## Questions and general discussion

Use GitHub Discussions for questions, ideas, and community conversation:

**[https://github.com/WeLikeCode/mintkey/discussions](https://github.com/WeLikeCode/mintkey/discussions)**

Issues are not for questions — they are for confirmed bugs and tracked feature
requests. Off-topic issues will be closed and redirected here.

---

## Feature requests

Use the feature request issue template:

**[Open a feature request](https://github.com/WeLikeCode/mintkey/issues/new?template=feature_request.yml)**

Architectural proposals (changes to wire contracts, auth schemes, tenancy model,
audit model) must follow the proposal → ADR path described in
[`CONTRIBUTING.md`](CONTRIBUTING.md) before a PR is raised.

---

## Security vulnerabilities

**Do NOT open a public issue for security problems.**

Report privately by emailing `the+security@ciprianiacobescu.com`. See
[`SECURITY.md`](SECURITY.md) for the full disclosure policy, scope, and
expected response timeline.

---

## Production support

Mintkey is pre-alpha. **Self-hosted evaluation is the only supported posture.**
There is no managed service, no hosted instance, and no production support
offering. See [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md) for the operator
guide with an explicit "unsupported but possible" production section.

---

## Response time

Best-effort. Pre-alpha. No SLA.
